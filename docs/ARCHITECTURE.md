# بنية إصدار الويب المعتمد

المضيف يفهم اللغة ويؤلف الشفرة ويتبع المصادر المختارة؛ لا نضيف نموذجًا أو محرك تخطيط بديلًا. `scripts/nasaq.py` مدخل موحد لإجراءات حتمية، مع إعادة استخدام `project_session.py` و`spec_kit_bridge.py` والفاحصين. التعليمات الأصلية تمر في handoff مسجل قبل تسليم المخرجات. لا تسمى هذه الطريقة تكاملًا أصليًا.

نواة صغيرة تحفظ القرارات والتفويض واللغة والحالة والأدلة. قفل كاتب واحد وجريدة طلب معلقة يمنعان إعلان نجاح بعد انقطاع غير محسوم. استعادة الحالة لا تعيد أمرًا خارجيًا تلقائيًا. تظل حالة مراحل Spec Kit مملوكة لـ`run.json`؛ لا تنسخ إلى منسق آخر.

المحولات اللاحقة تصف المصدر المثبت والفعل والاعتماديات والمخرجات والأدلة والبوابات. المكتبات والأدوات الأصلية تنفذ تخصصها. مالك واحد للعقد والبيانات والتصميم؛ حدود كتابة مستقلة لكل مكون. مصدر غير متاح ينتج حجبًا صريحًا، ولا بديلًا غير مأذون.

الأدلة الجديدة داخل `.nasaq-local/web-release-1/`، ومصدر المنتج الحالي في `skills/nasaq/`. سجل المصادر المقترح ليس قفل تشغيل؛ ينشأ القفل بعد مطابقة المصدر وحل الاعتماديات ومراجعتها. التوزيع لا يتضمن مصادر الغير أو البيئات أو بيانات المشاريع الخاصة. تثبيت المضيف خاص بجذر الاختبار ومملوك ببيان قابل للتحقق.
