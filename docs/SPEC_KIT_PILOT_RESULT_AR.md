# نتيجة تجربة نَسَق × Spec Kit — 2026-10-09

**اكتملت تجربة التخطيط المحدودة باللغتين عبر workflow-reference.** استخدم الوكيل تعليمات المصدر الأصلية وأنتج المخرجات؛ نفذ موصل نَسَق سكربتات المصدر المراجعة وحفظ التسليم والحالة والأدلة. ليس هذا استدعاءً أصليًا داخل المضيف، ولا تطبيق حجوزات منفذًا أو اختبارًا لجودته.

## المصدر والمراجعة

- المستودع الرسمي `https://github.com/github/spec-kit.git`؛ الإصدار المعتمد v1.1.2، commit `959e866caa3618bf3dc290d5dca33394365af9c6`.
- جُلب commit بعينه إلى مجلد التجربة، ثم تحقق HEAD وorigin ونظافة checkout قبل بدء كل مسار؛ بصمات الملفات المراجعة محفوظة في source-lock لكل تشغيل. الوسم غير موقع كما أوضحت بطاقة الموافقة؛ لا ادعاء تحقق توقيع.
- قرأت تعليمات constitution/specify/clarify/plan/tasks/analyze وقوالبها، وcommon.ps1 كاملًا ومحلل القوالب وسكربتات تهيئة الخطة والمهام وفحص المتطلبات. الرخصة MIT باسم GitHub محفوظة مع المصدر.
- لم يُثبت CLI أو اعتماد جديد. شُغلت `resolve-template.ps1` و`check-prerequisites.ps1` و`setup-plan.ps1` و`setup-tasks.ps1` فقط، مع common.ps1، من خلال الموصل. لا hooks أو presets أو extensions. استُخدم `pwsh -NoProfile` مع جذر وتجهيز مؤقت محليين.

## ما حدث عبر نَسَق

1. حُفظ طلب «نسق خطط» العربي والطلب الإنجليزي المكافئ. أضاف الوكيل افتراضات تجربة معلنة: مورد واحد، مواعيد مسبقة، هوية قائمة وإلغاء قبل البداية. ليست إجابات منسوبة للمستخدم أو قرارات منتج معتمدة.
2. أنشأ `spec_kit_bridge.py` سجل اختيار مر بالفاحص، وربطه بطلب المستخدم والنسخة المراجعة، ثم سجل `nasaq_request_routed` قبل مراحل العمل.
3. لكل مرحلة، `begin` قرأ تعليمات المصدر كاملة، شغّل سكربتها المراجعة، وحفظ handoff يتضمن الطلب والمدخلات وبصماتها. طبق الوكيل التعليمات وكتب المحتوى؛ الموصل لا يحتوي مولد مواصفات أو قوالب بديلة. `complete` سجل الملفات والبصمات وملاحظة التطبيق.
4. بعد constitution وspecify، أوقفت كل تجربة عمدًا، وحفظت snapshot للمخرجات وأوقات تعديلها. استؤنف كل مسار بعملية جديدة من clarify، دون إعادة specify أو تعديل مخرجاته.
5. أنتجت plan وثائق البحث والنموذج والعقد ودليل التحقق المستقبلي، ثم tasks خمسة عشر بندًا غير منفذ، ثم analyze تقريرًا للقراءة فقط. حفظ نَسَق نص التقرير كدليل ولم يعدل التحليل وثائق المنتج.

السكربتات `write_*_outputs.py` داخل التجربة وسائل لحفظ ردود الوكيل المؤلفة في هذه الجلسة بعد handoff؛ ليست محرك Spec Kit أو مولدًا عامًا بديلًا. السجل لا يثبت وحده جودة اتباع الوكيل؛ تعليمات المصدر والردود والمخرجات متاحة للتدقيق. لم يُستخدم نموذج مستقل أو مراجع بشري لتقييم الجودة.

## المشكلات والقيود

- أخفق مساعد إعداد سجل المراجعة أولًا بسبب مستوى مسار import؛ صُحح قبل تهيئة المسارين أو تشغيل أي سكربت مصدر. رفض الموصل السجل المفقود ولم يتجاوزه.
- أخفق أمر shell مركب لالتقاط حالة التوقف قبل التنفيذ؛ أعيد كملف Python واضح. كانت مسودة تقرير clarify قد كُتبت قبل handoff بسبب ذلك؛ جرى فحصها واعتمادها بعد handoff الصحيح، وسُجل هذا التسلسل صراحة في application_note. لم تتأثر المواصفات أو نتائج المصدر.
- الاستئناف المثبت بين مراحل مكتملة؛ التعافي التلقائي من توقف داخل مرحلة أو إعادة التخطيط بعد تعديل المدخل غير منفذ. الموصل يرفض هذه الحالات ويطلب معالجة صريحة، ولا يعيد استخدام أدلة قديمة.
- الموصل محدود بالـcommit المعتمد، وكاتب واحد، ومجلد ميزة واحد. لا تزامن كتّاب أو اكتشاف أصلي لمهارات المضيف أو دعم مثبت لمضيف آخر.
- العربية تشمل الطلب والمواصفات وأوصاف المهام وملخص الخطة؛ بعض تفاصيل الخطة ومراجعها وعناوين المصدر بقيت بالإنجليزية. لم يُجر تقييم ترجمة مستقل.
- لم يُبن التطبيق أو تُنفذ اختبارات تزامنه/أمانه أو واجهته. هذه اختبارات قبول مستقبلية في الوثائق، وليست نجاحات محسوبة هنا.
