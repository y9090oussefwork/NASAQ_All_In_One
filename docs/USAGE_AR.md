# استخدام نَسَق في Codex

## الإعداد مرة لكل مشروع

نزّل حزمة الإصدار وفكها، ثم انسخ مجلد `nasaq` إلى `.agents/skills/` داخل مشروع تجريبي أولًا. احتفظ بكل المجلدات الداخلية. لا تعدل إعدادات Codex العامة. هذا مسار مهارة داخل المشروع، وليس تطبيق ويب له خادم مستقل.

المتطلبات: Codex يعمل بحساب ونموذج متاحين، Python 3.11+ وGit لمسارات النواة. تثبيت PostgreSQL أو Node أو مصادر التخطيط ليس مطلوبًا لقراءة التعليمات؛ يحتاجه المسار الذي ستعتمده لاحقًا.

افتح جلسة جديدة، ثم اطلب «نسق، ابدأ» أو اختر nasaq من المهارات. لا حاجة لطلب قراءة SKILL.md في كل رسالة؛ إذا لم يكتشفه المضيف، راجع مكان المجلد وأعد الجلسة. اختبار القراءة الصريحة السابق لا يضمن الاكتشاف التلقائي في كل إصدار مضيف.

## أمثلة

- جديد: «نسق، أريد موقع حجز مواعيد بالعربية والإنجليزية. اجمع المتطلبات ولا تبدأ التنفيذ بعد».
- قائم: «نسق، افحص هذا المشروع بالقراءة فقط واشرح الموجود والمخاطر».
- تحكم: «نفذ حتى نهاية التخطيط ثم توقف» أو «أكمل المراحل المعتمدة، وتوقف عند تكلفة أو صلاحية جديدة».
- استئناف: «نسق، أكمل الحالة المحفوظة وافحص آثار الانقطاع قبل إعادة أي خطوة».
- لغة: «نسق، استخدم الإنجليزية».

اعتمد المتطلبات والمصادر بعد عرضها. Spec Kit يحتاج checkout رسميًا مثبتًا: v1.1.2، commit `959e866caa3618bf3dc290d5dca33394365af9c6`. اطلب من الوكيل إعداد مسار المصدر وفق `references/web-integration.md` بعد مراجعة الاعتماديات. لا يُنزّل تلقائيًا لمجرد تثبيت نَسَق.

احتفظ بمجلد `.nasaq` الخاص بمشروعك لاستئناف العمل؛ لا تنشر سجلاته دون مراجعتها. الموافقات في JSON سجل للمضيف وليست مصادقة هوية. لا تنسب إلى ملف مولد تنفيذ مصدر أو اجتياز اختبار.

## ما الذي تتوقعه؟

تلخيص متطلبات واختيارات وخطة ومهام وأدلة محددة حسب المصدر المجهز. التنفيذ يعتمد على الوكيل والمصادر والصلاحيات؛ لا يوجد ضمان تلقائي لجودة المنتج. التجارب السابقة لا تعني أن كل مشروع جديد سيعمل بلا تكييف.

راجع [وثائق مهارات Codex الرسمية](https://developers.openai.com/codex/skills/) و[حدود الإصدار](RELEASE_STATUS.md). لا تتجاوز عزل المضيف لحل مشكلة تشغيل؛ عالج إعداد المضيف أو استخدم بيئة مناسبة.
