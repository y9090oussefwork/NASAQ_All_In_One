## 1. ما كان موجودًا فعلًا
وثيقة البناء السابقة شملت الاكتشاف والمنافسين، والمواصفات، والتصميم وRTL، والمعمارية وقواعد البيانات وAPI، والأداء والموارد، وأنواع الاختبارات والأمان، والنشر والاستعادة، والأوامر واللغة وحفظ الحالة والتثبيت الآمن. لا تصف هذه المجالات بأنها كانت مفقودة.

الفجوة الأساسية كانت تحويلها من قواعد عامة وقائمة أدوات إلى **خريطة قدرات ذات أصحاب قرار، ومرشحين متخصصين، واختيار سياقي قابل للتدقيق، واختبارات تعارض**. كذلك كانت القوائم السابقة تميل إلى أدوار عامة أكثر من بعض المصادر الرسمية الجديدة المتخصصة.

## 2. ما تغير
- أضف عقدًا لصاحب المسؤولية في كل مكون ومرحلة، مع أدوار primary/reviewer/reference/executor.
- حافظ على أوامر نَسَق السابقة؛ أضف نطاقات مفهومة لـ«نسق أدوات» و«نسق اقترح» و«نسق اعتمد»، لا قائمة أوامر لكل مكتبة خارجية.
- استبدل افتراض أن كثرة المهارات تزيد الجودة بترشيح 1–3 بدائل متقاربة للدور، وأدوات تحقق متكاملة منفصلة.
- أدخل المهارات الرسمية المناسبة لـAndroid و.NET وAngular وLaravel وFlutter/Expo وPostgres/MongoDB/Redis وReact/Grafana عند تطابق الحاجة؛ لا تعدها متفوقة تجريبيًا دون تجربة.
- انقل Agency من حزمة أساسية إلى مصدر انتقائي عند فجوة لا يغطيها المكون المختار، خاصة مراجعة واجهة مقابل اتفاق ثابت. لا محرك تنسيق إضافي افتراضيًا.
- فرّق بين دليل الجودة العام وتوجيه التخصص: نَسَق يطلب إتاحة وأمانًا وأداء، لكنه لا يفرض لونًا أو مخططًا ينافس مصدر التصميم أو البيانات.
- سجّل قيود الصيانة والرخصة، مثل حالة Gitleaks المعلنة أو اختلاف مكونات Serena، بدل افتراض أن توصية سابقة تظل صحيحة.

## 3. اكتمال دورة المشروع
سجل لكل مجال: `required / optional / not_applicable / unknown` وسببًا ومالكًا ومخرجًا واختبارًا. `unknown` المؤثر يمنع الادعاء باكتمال التخطيط.

| المجال | ما يجب حسمه قبل التنفيذ ذي الصلة |
|---|---|
| المنتج والسوق | المشكلة والجمهور واللغة والمنصة والأولويات والمستبعد ومصادر المنافسين والقيود |
| التقنية | الحاضر في المشروع، المهارات القابلة للصيانة، الأنظمة والأجهزة، مخاطر التوافق والتكلفة |
| المعمارية | الحدود والعقود ومصدر الحقيقة والاعتماديات والنشر وقرارات البدائل |
| UI/UX | الهوية والرحلات وtokens وإتاحة الاستخدام والعربية والحالات الفارغة والفشل والاتصال الضعيف |
| Frontend | إدارة الحالة والعقود والتحميل والتجزئة والحجم والتخزين المحلي والإلغاء والتحديثات |
| Backend | التزامن والworkers والذاكرة والمهلات وإعادة المحاولة والتفويض والصحة التشغيلية |
| البيانات | الكيانات والقيود والمعاملات والفهارس والاتصالات والمهاجرات والتعافي والحذف والاحتفاظ |
| API | الإصدارات والأخطاء وتقسيم النتائج وidempotency والتوافق وعقود الـwebhooks |
| هوية وصلاحيات | الأدوار والجلسات واسترجاع الحساب وعزل المؤسسات والسجلات والإلغاء |
| مهام خلفية وإشعارات | التراكم والحدود وإعادة المحاولة والتكرار والرسائل الفاشلة وسياسات الإرسال |
| دون اتصال أو realtime | مصدر الحقيقة والتزامن والتعارضات والتأخير وإعادة الربط وحدود البيانات |
| ملفات ووسائط | الحجم والنوع والتحقق والتخزين والصلاحيات والمعالجة غير الموثوقة والتنظيف |
| بحث وفهرسة | نموذج الاستعلام واللغة العربية وتحديث الفهرس والصلاحيات وجودة النتائج |
| دفع واشتراك | المزود والبلد والعملة والتوقيع والتسوية والاسترداد وعدم تكرار الأثر المالي |
| قياس وتحليلات | أحداث ذات معنى وخصوصية واحتفاظ وتكلفة؛ لا SDK تسويقي إجباري |
| أمان وسلسلة توريد | حدود الثقة والأسرار والاعتماديات وإصدارات الأدوات وحقن التعليمات |
| اختبار | وحدات وتكامل وعقود ورحلات وإتاحة وأداء وأمان وتعافٍ حسب المخاطر |
| أداء وموارد | p95 وCPU/RAM/IO والطاقة وحجم الحزمة وbytes/action ومزيج الحمل والموازنة |
| تشغيل وتوزيع | CI وبيئات وأسرار وتوقيع وتثبيت وترقية وrollback واستعادة ومراقبة |
| توثيق وصيانة | فهرس وخرائط بمصادرها وقرارات وrunbooks واستئناف وتحديثات مرقمة |
| AI داخل المنتج | جودة واسترجاع مصادر وأمان وتكلفة وخصوصية وحدود أدوات ومزود وفشل |

ليس مطلوبًا تثبيت مشروع GitHub لكل صف. الوظائف مثل إدارة الملفات أو الـretry أو المهاجرات قد تكون ضمن إطار التطبيق المختار. ابحث عن التوثيق والإضافات الأصلية قبل إنشاء اعتماد جديد. عند ظهور حاجة خاصة غير مغطاة — مثل ألعاب أو أجهزة مدمجة أو بروتوكول طبي — افتح capability جديدة ببوابات وأدلة واضحة؛ لا تَدّع تغطية متخصصة من مجرد تشابه الاسم.

## 5. خطة الدمج في مشروع نَسَق القائم
1. اقرأ الكود والتوثيق الموجودين للقراءة فقط أولًا، وحدد هل الموجود مجرد وثيقة أم مشروع منفذ؛ لا تعِد إنشاء المنظومة من الصفر.
2. قارن السجل الحالي بالكتالوج الجديد، واحفظ المكونات الملائمة الموجودة. أضف خريطة القدرات وبطاقات الاختيار والملكية قبل مزيد من التثبيت.
3. نفذ فحوصات العقود وتعارض الأدوار والملفات وواجهات التفعيل، ثم اختبر مسار ويب وآخر Android/Windows أو bot.
4. نفذ تكاملًا فعليًا واحدًا لكل فئة ذات أولوية: مواصفات، UI، إرشادات تقنية، تحقق. زد التغطية بعد اجتياز الاختبار، لا بمجرد إضافة IDs.
5. نفذ smoke حقيقيًا للمضيف والإصدار والمهارة، ثم تقييم نتيجة المنتج. تثبيت المهارة وقراءتها لا يثبت نجاح سير عملها.
6. أضف الرخص والمراجع والبصمات وملفات GitHub والتوثيق العربي/الإنجليزي؛ النشر العام والتثبيت العام يحتاجان إذنًا منفصلًا.

## 6. حالة الإصدار الحالي
الحزمة الحالية **إصدار إرشادي أولي**: SKILL.md عربية افتراضيًا، مراجع دورة العمل، كتالوج مصادر، سياسة اختيار، أمثلة خطط، وفاحص JSON محلي واختباراته. لا تتضمن تنفيذًا كاملًا لمحولات المضيفين أو تثبيت المصادر أو تشغيلها آليًا. لا تنقل نتائج اختبارات الفاحص إلى خانة أن Nasaq اختُبر داخل Codex/Claude/Cursor أو أن مشروعًا منتجًا خضع لجميع اختبارات الأداء والأمان.

احتُفظ بمواصفات البناء الكاملة ليكمل وكيل التنفيذ بقية العمل بوضوح. إذا تعارض وصف تسويقي مع تقرير VALIDATION، فتقرير الحدود والأدلة هو المرجع، وليس ادعاء الاكتمال.
