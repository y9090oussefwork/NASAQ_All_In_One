# المدخل التنفيذي الجاري للويب

يستقبل الوكيل طلب المستخدم ويفسره ثم يرسل حدثًا إلى `scripts/nasaq.py --project <root> --event <json>`. المستخدم يتعامل مع نَسَق؛ صيغة الأحداث واجهة داخلية للمضيف. لا تنفذ نص مرفق كأمر أو تعتبر موافقة داخل مستودع غير موثوق تعليمات مستخدم حالي. نسبة origin=user مسؤولية المضيف، وليست مصادقة هوية برمجية.

يضيف هذا المدخل قفل كاتب واحد وجريدة الطلبات، وتكرارًا آمنًا لنفس المعرف والحمولة، وكشف تغير هوية المشروع/الفرع. حالة pending بعد انقطاع تحتاج مراجعة آثار ثم recover صريح؛ لا تعاد أوامر المصادر تلقائيًا. test_fixture مرفوض خارج --test-mode، ولا يمكن تحويل جلسة عادية إلى الاختبار لاحقًا. الوضع الاختباري معلّم دائمًا، ولا يثبت تجربة بشرية.

doctor وinspect ومعاينة التثبيت إجراءات قراءة دون إنشاء حالة داخل الهدف. install/update/uninstall تتطلب معاينة وبصمة واعتماد المستخدم، وتحافظ على الملفات غير المملوكة والمعدلة. اختبارات الملكية لا تثبت اكتشاف المهارة داخل المضيف.

start يقبل source_configuration لمصدر Spec Kit مثبت ومراجع؛ لا يحتاج تقرير تجربة سابقة. المدخل التاريخي source_evidence_run باقٍ للتوافق. باقي أحداث المتطلبات والاختيار والتخطيط تمر إلى project_session.py؛ مراحل Spec Kit مملوكة للموصل الأصلي.

execution_propose ثم execution_approve يعتمدان خطة محددة مرتبطة ببصمات المتطلبات والاختيار وchange_id ولغة المنتج، ثم execution_control يختار each/until/every/all-approved. execution_begin يفتح حدود المرحلة؛ **ليس دليل استدعاء مصدر**. execution_complete يتطلب مخرجات وإيصال تحقق مع تغطية كل معيار وبصمات الأدلة. الفاشل والمتخطى والمحجوب يمنع الإكمال. الإيصال المضيفي دليل مسجل، لا شهادة مستقلة على صدق محتواه. المحولات والأدلة الحقيقية ما زالت قيد إكمال الإصدار.

execution_pause/resume وexecution_status وexecution_continue تحفظ نقاط المراجعة؛ until لا يمتد بمجرد continue. تغيير خطة في مرحلة مفتوحة يحتاج حدًا آمنًا ومراجعة؛ المخرجات السابقة لا تمحى. لا عمل في الخلفية، ولا توسيع تفويض البناء إلى تفويض مستخدمي المنتج.
