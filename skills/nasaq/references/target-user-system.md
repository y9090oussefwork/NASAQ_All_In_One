# نظام الاستخدام المستهدف لنَسَق

قرار مستخدم معتمد بتاريخ 2026-10-09. يثبت الوجهة ولا يمنح إذن تنفيذ أو تثبيت إضافيًا. يظل [تقرير المحادثة](../../../docs/NASAQ_CONVERSATION_RESULT_AR.md) دليل النطاق المنفذ، و[خطة التجربة التالية](../../../docs/NASAQ_NEXT_INTEGRATION_PLAN_AR.md) مقترحًا ينتظر الموافقة.

نَسَق نقطة اتصال عربية/إنجليزية واحدة داخل المضيف. بعد إعداده واختبار اكتشافه مرة واحدة، يستدعيه المستخدم باسمه؛ يحمّل الوكيل تعليماته داخليًا. لا يطلب من المستخدم قراءة SKILL.md أو تشغيل أوامر المصادر عند كل مشروع. هذا هدف إعداد لم يُختبر بعد في جلسة مضيف جديدة.

| الخطوة المستهدفة | الحالة الحالية وحدودها |
|---|---|
| 1. شرح مشروع جديد أو قائم بأي من اللغتين | الجديد له مسار محفوظ حتى التخطيط؛ القائم يوجَّه لفحص الوكيل للقراءة فقط، وليس له مسار تنفيذ مكتمل |
| 2. جمع المميزات والاستيضاح المؤثر فقط | الوكيل يستخرج الحقائق والأسئلة؛ المساعد يحفظها ويمنع الاعتماد مع نقص مؤثر. لا فهم لغوي مستقل |
| 3. معلومات وملفات دفعة واحدة أو سؤالًا بسؤال | الحقائق المجمعة والجولات مختبرة ببيانات افتراضية؛ قراءة المرفقات تعتمد على أدوات الوكيل وليست قناة استيراد مختبرة |
| 4. طلب المنافسين عند الحاجة أو عرض البحث المناسب | تعليمات للوكيل وحقل competitors؛ لا تكامل بحث أو اختبار رحلة منافسين. احترم موافقات الأدوات ومشاركة البيانات والتكلفة |
| 5. ملخص قابل للتعديل | منفذ مع بصمة واعتماد وإبطال الاعتمادات المتأثرة |
| 6. ترشيحات بأسباب وبدائل وحالة اختبار | الوكيل يصوغ المقترح؛ المساعد يتحقق من بنيته ويعرض الجاهزية. لا محلل توافق أو محرك توصية مستقل، ولا حقل بدائل إلزامي حاليًا |
| 7. اختيار يدوي أو قبول أو تفويض مقيد | منفذ في نطاق اختيار التخطيط؛ اعتماد الاختيار ليس إذن تنفيذ |
| 8. تخطيط بالمصادر المختارة | مصدر تخطيط واحد قابل للتشغيل: Spec Kit بالنسخة المراجعة؛ بقية المرشحين لا تُستدعى |
| 9. عرض خطة التنفيذ وتعديلها واعتمادها | تُنتج الخطة والمهام؛ لا بوابة اعتماد تنفيذ تطبيق أو دورة تعديل تنفيذية مكتملة بعد |
| 10. التصميم والواجهة والخادم والبيانات والاختبارات | تحتاج تكاملات فعلية؛ الكتالوج ليس دليل تشغيل |
| 11. تحقق وحالة وتغييرات وأدلة لكل مرحلة | بصمات وحالة وأدلة مراحل التخطيط منفذة؛ جودة المحتوى يراجعها الوكيل. اختبارات التطبيق والمناولة بين التخصصات لم تُنفذ |
| 12. تسليم مشروع قابل للتجربة وتقرير صريح | تسليم وثائق التخطيط متاح؛ تسليم تطبيق متكامل غير مختبر |

## التحكم والقرارات

الأوضاع المستهدفة: بعد كل مرحلة رئيسية، حتى مرحلة محددة، كل عدد مراحل، أو جميع المراحل المعتمدة. المنفذ يطبقها على مراحل Spec Kit الست فقط. المرحلة التالية توسع النطاق بعقود وموافقات صريحة، ولا تغيّر معنى موافقات التخطيط القديمة. اسم المرحلة يترجم إلى معرف داخلي، ولا يلزم أن يحفظ المستخدم أرقامًا أو أوامر.

يمكن تغيير الوضع أو تعديل المشروع أثناء العمل. ما نُفذ: تعديل المتطلبات/الاختيار يبطل الاعتماد المتأثر ويحفظ التشغيل السابق؛ الاستئناف يتحقق من المخرجات المكتملة. ما ينقص: تحليل أثر تعديلات التطبيق ومهاجرة البيانات والتراجع عن التنفيذ والتعافي من كل أنواع الانقطاع. pause لا يعني قتل عملية بدأت بالفعل؛ التنفيذ الحالي متزامن ولا يستقبل تغييرًا في منتصف استدعاء سكربت.

لا تشمل الموافقة العامة النشر أو حذف بيانات إنتاجية أو التثبيت العالمي أو شراء خدمات أو كشف أسرار. بوابات نَسَق سجلات محلية وليست عزلًا أمنيًا؛ أداة المضيف تظل حد الصلاحيات. لا عمل خلفي أو تنبيهات إلا بدعم فعلي واختبار صريح؛ احفظ الحالة للاستئناف عند غيابهما.

## الإدارة الهجينة للمصادر

1. فضّل المصدر الرسمي بنسخة وcommit ثابتين وبصمات الملفات والحزم المستخدمة.
2. احتفظ بنسخة محلية معتمدة عند الحاجة وسماح الترخيص، مع الرخصة والإشعارات.
3. أنشئ fork فقط لتعديل أو صيانة خاصة مبررة، وسجل الفرق وخطة صيانته.
4. راجع التحديثات واختبر التوافق قبل الترقية؛ لا تستخدم latest ضمن تشغيل مثبت.
5. احتفظ بالنسخة السابقة وقفلها وأدلة توافقها لإمكان الرجوع. الرجوع للمصدر لا يعني تلقائيًا إمكان الرجوع لمخطط قاعدة بيانات التطبيق.

يسجل كل تكامل المصدر والرخصة والنسخة والاعتماديات وطريقة الاستخدام والنطاق المختبر. الموجود مثال Spec Kit المحلي؛ نظام تحديثات وترقية وتراجع عام ما زال مستهدفًا. لا forks جماعية ولا تثبيت للكتالوج كله.
